# AI Football Performance Department

Claude Code를 하나의 **Football Performance Department**로 운영하기 위한 저장소입니다.
당신은 Head Performance Coach이고, Claude는 16개 전문팀(연구, 데이터, S&C, sprint, 부상, 영어, 콘텐츠 등)으로 구성된 부서로서 당신의 판단을 지원합니다.

---

## 1. 시작하기

1. [claude.ai/code](https://claude.ai/code) (또는 Claude 앱의 Code 탭)에서 **새 세션**을 열고 저장소로 `Physical-sience`를 선택합니다.
2. 세션이 열리면 Claude는 `CLAUDE.md`(운영체계)를 자동으로 읽습니다. 따로 설정할 것은 없습니다.
3. 입력창에 `/research` 뒤에 원하는 것을 한국어나 영어로 자유롭게 씁니다.

```
/research 햄스트링 부상 예방에 대한 최신 연구 정리해줘
```

> 명령어 없이 그냥 질문해도 됩니다. `/research`를 붙이면 분류 → 담당 팀 → 절차 → 저장까지 정해진 방식대로 더 꼼꼼하게 처리합니다.

---

## 2. 명령어는 `/research` 하나

`/research` 하나로 모든 작업을 처리합니다. Claude가 요청을 읽고 작업 유형을 자동으로 고릅니다.
원하는 유형을 확실히 지정하고 싶으면 **앞에 키워드를 붙이세요** (선택 사항).

| 앞에 붙이는 키워드 | 하는 일 | 예시 |
|------------------|--------|------|
| (없음) / `연구:` | 논문 조사, 근거 수준 평가 | `/research 연구: 정적 스트레칭이 sprint에 미치는 영향` |
| `분석:` | 선수 데이터 해석 | `/research 분석: (CMJ, RPE 데이터 붙여넣기)` |
| `데이터:` | 무엇을 측정·기록할지 설계 | `/research 데이터: U15 팀 매일 wellness 모니터링 시트` |
| `프로그램:` | 훈련 프로그램 설계 | `/research 프로그램: U18 윙어 4명, 인시즌 주 1경기, 8주 sprint 향상` |
| `sprint:` / `COD:` / `플라이오:` | 전문 분석 | `/research sprint: 첫 5m가 느린 풀백, 원인과 훈련` |
| `회복:` / `영양:` | 피로·회복·영양 | `/research 회복: 주 2경기일 때 MD+1 회복 전략` |
| `부상:` | 부상 위험, 부하 관리, 복귀 지원 | `/research 부상: 햄스트링 부상 이력 선수 sprint 노출 관리` |
| `축구:` | 포지션·전술별 physical demand | `/research 축구: 하이프레싱 팀 윙백의 경기 요구` |
| `영상:` | 영상(캡처) 움직임 분석 | `/research 영상: (프레임 캡처 이미지 첨부) 감속 동작 분석` |
| `영어:` | Football English | `/research 영어: staff meeting에서 훈련량 줄이자고 제안하는 표현` |
| `콘텐츠:` / `전자책:` | 인스타·유튜브·블로그·전자책 | `/research 콘텐츠: 인스타 carousel, "스트레칭 신화"` |
| `커리어:` | 자격증, CV, 1/3/5년 계획 | `/research 커리어: 3년 안에 유럽 유소년 클럽 피지컬 코치` |
| `프로젝트:` | 진행 상황, 다음 할 일 | `/research 프로젝트:` (비워두면 전체 현황) |
| `팀:` | 어떤 전문팀이 필요한지 구성 | `/research 팀: 시즌 중반 팀 전체 sprint 속도 저하` |
| `회의:` | 여러 팀이 토론하고 결론 | `/research 회의: CMJ가 12% 떨어진 센터백, MD-1 훈련 참여 여부` |
| `보고서:` | 최종 Performance Report | `/research 보고서: 이번 달 U18 sprint 프로젝트 결과` |
| `공부:` | 답 대신 생각하는 과정을 같이 | `/research 공부: 왜 발바닥 마사지로 ankle ROM이 늘어날까?` |

## 3. 좋은 결과를 받는 요청 쓰는 법

Claude는 정보가 부족하면 **가정을 밝히고 먼저 진행**합니다. 아래 정보를 줄수록 결과가 현장에 가까워집니다.

| 항목 | 예 |
|------|----|
| 누구 | U18, 남자, 윙어, 훈련 경력 3년, 세미프로 |
| 언제 | 프리시즌 / 인시즌, 주 1경기 / 주 2경기, 다음 경기 토요일 |
| 목표 | 첫 10m 가속 향상, 햄스트링 재부상 위험 관리 |
| 제약 | 주 2회 30분, 웨이트 장비 없음, 잔디 구장만 |
| 이력 | 6개월 전 햄스트링 부상, 현재 통증 없음 |
| 데이터 | CMJ, 10m 기록, GPS HSR, RPE (있는 만큼) |

**나쁜 예:** `/research sprint 프로그램`
**좋은 예:** `/research 프로그램: U18 윙어 4명, 인시즌 주 1경기(토), 화·목 30분 가능, 목표 10m 가속, 1명은 6개월 전 햄스트링 부상`

---

## 4. 데이터 넣는 법

- **짧은 데이터**: 채팅에 표나 숫자를 그대로 붙여넣으세요.
- **파일**: CSV/엑셀 파일을 채팅에 첨부하거나 `data/` 폴더에 올린 뒤 `/research 분석: data/파일이름.csv`.
- **선수 이름 대신 코드**(P01, P02 …)를 쓰세요. 저장소에 개인 정보가 남지 않게 하기 위해서입니다.
- 가능하면 **기준값(baseline)** 과 **맥락**(경기 일정, 훈련 단계)을 함께 주세요. 숫자 하나로는 선수 상태를 판단하지 않습니다.

---

## 5. 결과물은 어디에 저장되나

다시 볼 가치가 있는 결과물은 자동으로 폴더에 저장되고, 세션이 끝나도 사라지지 않도록 GitHub에 올라갑니다(commit & push).

| 폴더 | 내용 |
|------|------|
| `research/` | 연구 노트 (+ `references/references.md` 참고문헌 목록) |
| `data/` | 데이터 분석 결과 |
| `training/` | 훈련 프로그램 |
| `injury/`, `recovery/` | 부상·부하 관리, 피로·회복·영양 |
| `football/` | 포지션·전술 요구 분석, 영상 분석 |
| `english/` | 영어 표현 모음 |
| `content/` | 콘텐츠 초안 (전자책은 `content/ebook/`) |
| `projects/` | 프로젝트 카드, 커리어 계획 |
| `reports/` | 보고서, 회의록 |

- 파일 이름: `2026-09-23_nordic-hamstring-meta-analysis.md` 형식
- GitHub 저장소 페이지에서 폴더를 눌러 언제든 읽을 수 있습니다.
- 간단한 질문과 답은 저장하지 않습니다. 저장하고 싶으면 "이거 저장해줘"라고 하세요.
- 예전 자료를 다시 쓰고 싶으면: `/research research/ 폴더의 햄스트링 노트를 바탕으로 인스타 콘텐츠 만들어줘`

## 6. 대화를 이어가는 요령

첫 답을 받은 뒤 같은 세션에서 이렇게 이어가면 됩니다 (명령어 필요 없음).

- `더 짧게, 현장 코치용 1페이지로`
- `근거 수준이 HIGH인 것만 남겨줘`
- `이걸 영어로 staff meeting에서 발표한다면?`
- `이 내용으로 인스타 carousel 만들어줘`
- `부상 팀 입장에서 반대 의견 내봐`
- `U15 선수라면 뭐가 달라져?`
- `저장하고 프로젝트 보드 업데이트해줘`

| 월 1회 | `/research 커리어:` — 1/3/5년 계획 점검 |

## 8. 알아둘 한계

- **의학적 진단과 처방은 하지 않습니다.** 통증, 부종 같은 신호가 보이면 **⚠ Refer to medical staff**로 표시합니다.
- **논문 인용**: 실제로 확인한 것만 인용하고, 확인하지 못한 것은 `unverified`로 표시합니다. 중요한 결정 전에는 원문을 직접 확인하세요.
- **영상**: 동영상 파일을 직접 재생하지는 못합니다. 중요한 장면을 **캡처 이미지**로 첨부하면 분석합니다.
- **최종 결정은 코치(당신)가 합니다.** Claude는 판단 근거와 선택지를 정리하는 역할입니다.
